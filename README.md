# Python 网络流量分析工具

用 Python 写的抓包分析工具。抓网卡上的数据包，逐包解析出源/目的IP、端口、协议和TCP标志位，结束后给出协议分布统计和通信目标排行，并且能检测端口扫描行为。

这是我的第二个安全小项目，和端口扫描器（p_scan）是一对：一个负责扫，一个负责看。实测用 p_scan 扫描本机，这个工具当场把扫描行为抓了出来。

## 能干什么

抓包过程逐包打印，结束后输出统计报告：

```
共抓取 1981 个数据包

协议   数量   占比
TCP    1981   100.0%

通信目标 TOP 10：
  127.0.0.1 > 127.0.0.1:5577  (405 包)
  ......

检测到疑似端口扫描：
  来源 127.0.0.1 在抓包期间触碰了 103 个不同端口
```

## 怎么跑

先装依赖：

```
pip install scapy rich
```

```
python sniffer.py                  # 抓默认网卡，抓50个包后停止
python sniffer.py -i loopback      # 监听本机回环，抓127.0.0.1的流量必须用它
python sniffer.py -c 100 -t 30     # 自定义抓包数量和超时秒数
```

看检测效果：一个窗口跑 `python sniffer.py -i loopback -t 20`，另一个窗口用端口扫描器扫自己，比如 `python p_scan.py 127.0.0.1 -p 1-100`，抓包结束就能看到扫描告警。

## 原理

数据包是分层结构（以太网帧 > IP > TCP/UDP），工具逐层取出字段来解析。

端口扫描的指纹：同一个来源，短时间内用纯SYN包（不带ACK）触碰大量不同的端口。工具按（源IP，目的IP）记录每个来源的SYN触碰过的端口集合，超过阈值（默认10个）就告警。正常上网对每个目标只会碰一两个端口，所以不容易误报。

## 踩坑记录

- Windows 上 127.0.0.1 的流量不走物理网卡走回环，不加 -i loopback 根本抓不到自己扫自己的包
- 不是所有包都有IP层（比如ARP），不判断就访问会直接崩，所以要先 `if IP in pkt`
- 抓包才发现本机后台流量比想象的多：代理、系统服务、设备发现协议都在跑

## 可以改进的地方

- 检测目前只统计端口数量，可以加时间窗口（比如10秒内超阈值才算）
- 检测结果导出成文件
- UDP 扫描还没处理

思路参考了 scapy 官方文档和常见抓包示例，配合端口扫描器项目 p_scan 使用效果最佳。
