# Python 网络流量分析工具

用 Python 写的抓包分析工具。抓网卡上的数据包，逐包解析出源/目的IP、端口、协议和TCP标志位，结束后给出协议分布统计和通信目标排行，并且能在滑动时间窗口内检测 TCP SYN 扫描和 UDP 扫描，报告可以导出成 JSON。

这是我的第二个安全小项目，和端口扫描器（p_scan）是一对：一个负责扫，一个负责看。实测用 p_scan 扫描本机，这个工具当场把扫描行为抓了出来。

## 能干什么

抓包过程逐包打印，结束后输出统计报告：

```
共抓取 1981 个数据包

协议   数量   占比
TCP    1981   100.0%

通信目标 TOP 10：
  127.0.0.1 > 127.0.0.1:5577  (405 包)
  ......

检测到疑似端口扫描：
  来源 127.0.0.1 在 0.8 秒内触碰了 127.0.0.1 的 103 个不同端口
```

加上 -o 参数还能把整份报告存成 JSON，方便丢给别的程序接着处理。

## 怎么跑

先装依赖：

```
pip install scapy rich
```

```
python sniffer.py                  # 抓默认网卡，抓50个包后停止
python sniffer.py -i loopback      # 监听本机回环，抓127.0.0.1的流量必须用它
python sniffer.py -c 100 -t 30     # 自定义抓包数量和超时秒数
python sniffer.py -w 5             # 扫描检测的窗口改成5秒，默认10秒
python sniffer.py -o report.json   # 抓完把报告导出成JSON
```

看检测效果：一个窗口跑 `python sniffer.py -i loopback -t 20 -o report.json`，另一个窗口用端口扫描器扫自己，比如 `python p_scan.py 127.0.0.1 -p 1-100`，抓包结束就能看到扫描告警，打开 report.json 能看到完整报告。

## 原理

数据包是分层结构（以太网帧 > IP > TCP/UDP），工具逐层取出字段来解析。

扫描检测用的是滑动时间窗口：按（源IP，目的IP）记录每次触碰，每来一个新包就把窗口外的旧记录扔掉，只数窗口内触碰过的不同端口，超过阈值（默认10个）就告警，然后清空重新计数。比起以前"整个抓包期间累计"，窗口化的好处是正常上网历史再长也不会误报，告警信息里还能带上"几秒内碰了多少端口"，扫描越快数字越吓人，一目了然。

TCP 和 UDP 分开跟踪。TCP 的指纹很硬：纯 SYN 包不带 ACK，就是半开扫描的典型样子。UDP 没有握手，扫完就跑，没有明确的信号，只能靠"短时间内打向大量不同端口"这个粗指纹，误报率比 TCP 高，这是协议本身的限制。

## 踩坑记录

- Windows 上 127.0.0.1 的流量不走物理网卡走回环，不加 -i loopback 根本抓不到自己扫自己的包
- 不是所有包都有IP层（比如ARP），不判断就访问会直接崩，所以要先 `if IP in pkt`
- 抓包才发现本机后台流量比想象的多：代理、系统服务、设备发现协议都在跑
- 时间窗口用 deque 存（时间戳，端口），每次新包进来从左边把过期记录挤出去，比每次全量遍历过滤省事
- UDP 检测最容易误报的是 mDNS、SSDP 这类服务发现协议，不过它们固定打 5353、1900 这一个端口，按"不同端口数"计数就避开了

## 可以改进的地方

- 只统计不同端口数，可以给端口加权重，比如触碰 3389、445 这种高危端口时降阈值
- 导出目前只有 JSON，可以加 CSV 方便用 Excel 打开
- 把 p_scan 的全连接扫描和半开扫描分别打一遍，对比两种模式被抓包看到的区别，写进 README

思路参考了 scapy 官方文档和常见抓包示例，配合端口扫描器项目 p_scan 使用效果最佳。
